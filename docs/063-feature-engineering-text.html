68  Feature Engineering for Text

Text is the most abundant and least structured data modality in modern machine learning. A document is a sequence of characters with no fixed length, no inherent numeric meaning, and no obvious alignment between examples. Before any statistical learner can operate on text, that sequence must be transformed into a finite vector of features. This transformation is the subject of feature engineering for text, and despite the dominance of large neural language models, the classical pipeline remains indispensable. It is fast, interpretable, cheap to deploy, and frequently competitive on the tasks that actually fill production backlogs.

This chapter develops the classical text feature pipeline from first principles: tokenization, bag of words, n-grams, term weighting with TF-IDF, and the hashing trick for scale. It then builds a bridge to distributed representations, word and sentence embeddings, and gives a sober account of when sparse classical features still outperform dense neural ones. It closes with a modern case study in which the feature space itself is induced by LLMs.

The pipeline is best understood as a sequence of maps from one representation to the next, each adding structure or shedding cost.

The top path is the sparse symbolic pipeline that dominates Sections 1 through 5. The lower paths are the dense semantic routes of Section 6. Section 7 explains when each is the right choice, and Section 8 studies a third route absent from this diagram entirely: feature spaces induced by LLMs.

68.1 1. From Characters to Tokens

68.1.1 1.1 The tokenization problem

A learner cannot consume raw bytes meaningfully, so the first step is to segment a string into discrete units called tokens. Tokenization sounds trivial in English, where whitespace approximates word boundaries, but it is full of decisions that materially affect downstream accuracy. Consider the string "Don't email me at jane.doe@acme.co!". Should Don't be one token, two (Do and n't), or three? Is jane.doe@acme.co a single semantic unit or five fragments? Each choice changes the feature space.

A simple regular expression tokenizer captures most word like spans:

import re
def tokenize(text):
    return re.findall(r"[A-Za-z0-9']+", text.lower())

This lowercases, splits on non alphanumeric characters, and keeps apostrophes. It is crude but reproducible, and reproducibility matters more than linguistic elegance because the same function must run at training and inference time. A subtle but consequential rule follows from this: the tokenizer and every normalization step are part of the model, not preprocessing performed once and discarded. Any divergence between the function applied to training data and the function applied at serving time is a silent source of degradation often called training serving skew, and the most reliable defense is to encapsulate the entire transform (in scikit-learn, a Pipeline) so that it is fit once and applied identically thereafter.

To fix vocabulary, define the type token distinction. A token is a single occurrence of a unit in a specific document, while a type is a distinct unit in the abstract vocabulary. The sentence the cat sat on the mat has six tokens but five types, since the occurs twice. The vocabulary is the set of types, and the dimension of the feature space is the number of types retained after pruning.

68.1.2 1.2 Normalization choices

Beyond segmentation, several normalization steps shrink the vocabulary and improve generalization. Lowercasing collapses The and the. Stemming reduces inflected forms to a root, so running, runs, and ran may all map toward run using a rule based algorithm such as the Porter stemmer. Lemmatization does the same but uses a dictionary and part of speech information to produce valid words, mapping better to good. Accent folding and Unicode normalization (NFKC) unify visually identical characters.

Each normalization trades precision for recall in the feature space. Aggressive stemming can merge university and universe, destroying a useful distinction. The right level of normalization is empirical and task dependent, and it should be tuned with cross validation rather than assumed.

68.1.3 1.3 Stop words and pruning

Function words such as the, of, and is occur in nearly every document and carry little discriminative signal for many tasks. Removing a stop word list reduces dimensionality and noise. However, stop word removal is not universally beneficial. For sentiment, the word not is decisive, and for authorship attribution function word frequencies are among the strongest signals. Modern practice often retains stop words and lets the weighting scheme downweight them, which is more robust than a hard list.

A related lever is frequency pruning. Tokens appearing in fewer than min_df documents are likely typos or noise, and tokens in more than max_df fraction of documents behave like stop words. Pruning both tails keeps the vocabulary compact and the model well conditioned. The shape of the count distribution makes this pruning especially effective. Word frequencies in natural language follow Zipf’s law: ranking types by frequency, the frequency of the type at rank \(r\) is approximately

\[ f(r) \approx \frac{C}{r^{s}}, \qquad s \approx 1, \]

so a small number of types account for most tokens while a long tail of types each occur once or twice. The long tail inflates dimensionality without adding usable signal, which is exactly why a modest min_df (say 5) can discard the majority of types while removing only a small fraction of total token mass.

68.2 2. The Bag of Words Model

68.2.1 2.1 Vector space representation

The bag of words (BoW) model represents a document as the multiset of its tokens, discarding order entirely. Given a vocabulary \(V = \{w_1, \dots, w_{|V|}\}\) extracted from the training corpus, a document \(d\) becomes a vector \(\mathbf{x}_d \in \mathbb{R}^{|V|}\) whose \(j\)th entry is the count of term \(w_j\) in \(d\):

\[ x_{d,j} = \text{tf}(w_j, d) = \sum_{t \in d} \mathbb{1}[t = w_j]. \]

Stacking all document vectors row wise yields the document term matrix \(X \in \mathbb{R}^{n \times |V|}\). This matrix is the central object of classical text mining. It is extremely sparse, since any single document uses a tiny fraction of the global vocabulary, so it is stored in compressed sparse row format and the model never materializes the zeros.

68.2.2 2.2 Why discarding order can work

Throwing away word order seems reckless, yet BoW is a strong baseline for topic level tasks such as spam detection, document categorization, and many sentiment problems. The reason is that for these tasks the presence of certain words is nearly sufficient: an email containing viagra, wire transfer, and urgent is probably spam regardless of arrangement. The signal lives in the marginal token statistics, which BoW captures exactly. Tasks that hinge on syntax or compositional meaning, such as the food was good but the service was not, are where BoW begins to fail, and the next section partially repairs this.

The bag of words assumption has a precise probabilistic reading. The multinomial naive Bayes classifier models a document of class \(c\) as a sequence of independent draws from a class conditional word distribution, giving

\[ P(d \mid c) = \frac{(\sum_j x_{d,j})!}{\prod_j x_{d,j}!} \prod_{j} P(w_j \mid c)^{x_{d,j}}. \]

The independence of draws is exactly the discarding of order, and the log likelihood is linear in the count vector \(\mathbf{x}_d\). This is why a linear classifier over BoW features is not an arbitrary choice but the natural decision rule under the bag assumption: maximizing the posterior reduces to a weighted sum of token counts plus a bias, which is precisely what logistic regression and the linear SVM also compute, learned discriminatively rather than generatively.

68.2.3 2.3 Geometry and similarity

Once documents are vectors, similarity becomes geometry. The dominant measure is cosine similarity, which compares orientation rather than magnitude and so is robust to document length:

\[ \cos(\mathbf{x}, \mathbf{y}) = \frac{\mathbf{x} \cdot \mathbf{y}}{\lVert \mathbf{x} \rVert \, \lVert \mathbf{y} \rVert}. \]

Cosine similarity on BoW or TF-IDF vectors underlies classical search ranking, nearest neighbor classification, and clustering. Its interpretability, every nonzero dimension corresponds to a literal word, is a property that dense embeddings sacrifice.

68.3 3. N-grams and Local Order

68.3.1 3.1 Capturing short phrases

A bigram is an ordered pair of adjacent tokens, a trigram an ordered triple, and in general an n-gram is a contiguous window of \(n\) tokens. By adding n-grams to the vocabulary, the BoW model recovers a limited but valuable amount of word order. The phrase not good becomes a single feature distinct from good, allowing a linear model to assign it negative weight. For the sentence New York is not Los Angeles, the bigrams new york and los angeles capture multiword entities that unigrams shatter.

68.3.2 3.2 The dimensionality cost

N-grams are powerful but expensive. If the unigram vocabulary has size \(|V|\), the space of possible bigrams is \(|V|^2\), and trigrams \(|V|^3\). In practice most n-grams never occur, so the realized count grows roughly linearly with corpus size rather than combinatorially, but the feature matrix still explodes from tens of thousands of columns to millions. This drives memory pressure and overfitting risk, and it is the primary motivation for the hashing trick in Section 5.

A common compromise is to include unigrams and bigrams (ngram_range=(1,2)) with aggressive min_df pruning, which captures the highest value local order while keeping the vocabulary manageable.

68.3.3 3.3 Character n-grams

N-grams need not be over words. Character n-grams, contiguous spans of characters, are remarkably robust. The word engineering yields character 4-grams engi, ngin, gine, and so on. Because they share substrings, character n-grams handle misspellings, morphological variation, and out of vocabulary words gracefully, and they require no language specific tokenizer. They are the workhorse of language identification, authorship attribution, and noisy social media text, and they are the conceptual ancestor of subword tokenization in neural models.

68.4 4. Term Weighting with TF-IDF

68.4.1 4.1 The intuition

Raw counts overweight common words. A term appearing in every document discriminates nothing, while a rare term that appears in only a handful of documents is highly informative when it does. TF-IDF (term frequency times inverse document frequency) formalizes this by scaling each count by how surprising the term is across the corpus.

68.4.2 4.2 The formulas

The term frequency component measures local importance. A common variant uses sublinear scaling to dampen the effect of repetition:

\[ \text{tf}(t, d) = 1 + \log\big(\text{count}(t, d)\big) \quad \text{for } \text{count}(t,d) > 0. \]

The inverse document frequency component measures global rarity. Let \(n\) be the number of documents and \(\text{df}(t)\) the number containing term \(t\). A standard smoothed form is

\[ \text{idf}(t) = \log\frac{1 + n}{1 + \text{df}(t)} + 1. \]

The TF-IDF weight is the product, and the resulting document vector is usually L2 normalized so that document length does not dominate:

\[ \text{tfidf}(t, d) = \text{tf}(t, d) \cdot \text{idf}(t), \qquad \hat{\mathbf{x}}_d = \frac{\mathbf{x}_d}{\lVert \mathbf{x}_d \rVert_2}. \]

The smoothing constants prevent division by zero and bound the IDF of terms absent from training. The logarithm in IDF reflects a diminishing returns view of rarity, consistent with an information theoretic reading where \(\text{idf}(t)\) approximates the self information of observing term \(t\) in a randomly drawn document. If \(P(t)\) is the probability that a random document contains \(t\), estimated by \(\text{df}(t)/n\), then the unsmoothed IDF \(\log\frac{n}{\text{df}(t)} = -\log P(t)\) is exactly the Shannon surprisal of the event that \(t\) appears. A term that occurs everywhere carries near zero surprisal and is heavily downweighted, while a term confined to a few documents carries high surprisal and is amplified. This is the formal sense in which TF-IDF measures specificity, as Sparck Jones argued in the founding paper on the idea (reference 3).

68.4.3 4.3 A worked example

Take a toy corpus of four documents over the terms cat, dog, and the.

Document cat dog the
\(d_1\) 2 0 3
\(d_2\) 0 1 2
\(d_3\) 1 1 1
\(d_4\) 0 0 4

Here \(n = 4\). The document frequencies are \(\text{df}(\text{cat}) = 2\), \(\text{df}(\text{dog}) = 2\), and \(\text{df}(\text{the}) = 4\). Using the smoothed form \(\text{idf}(t) = \log\frac{1+n}{1+\text{df}(t)} + 1\) with natural logarithm,

\[ \text{idf}(\text{cat}) = \log\tfrac{5}{3} + 1 \approx 1.51, \quad \text{idf}(\text{dog}) = \log\tfrac{5}{3} + 1 \approx 1.51, \quad \text{idf}(\text{the}) = \log\tfrac{5}{5} + 1 = 1.00. \]

The term the, present in every document, receives the floor weight of 1, while the rarer cat and dog are boosted. For document \(d_3\) with raw counts \((1, 1, 1)\) and sublinear term frequency \(1 + \log(1) = 1\) for each, the unnormalized TF-IDF vector is \((1.51,\ 1.51,\ 1.00)\). L2 normalization divides by \(\sqrt{1.51^2 + 1.51^2 + 1.00^2} \approx 2.34\), giving the final vector \((0.645,\ 0.645,\ 0.427)\). The common word the survives but is muted, and the two content words dominate the document’s direction in the vector space, which is exactly the behavior cosine similarity then exploits.

68.4.4 4.4 Why it remains a strong baseline

TF-IDF weighted vectors fed to a linear classifier such as logistic regression or a linear support vector machine form one of the most reliable baselines in applied natural language processing. The weighting is parameter free, the model is convex and trains in seconds on millions of documents, and the learned coefficients are directly inspectable. Before reaching for a transformer, a practitioner should establish this baseline, because surprisingly often it is within a point or two of far more expensive models, and it is the number every fancier method must beat.

from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
vec = TfidfVectorizer(ngram_range=(1,2), min_df=5, sublinear_tf=True)
X = vec.fit_transform(train_texts)
clf = LogisticRegression(max_iter=1000).fit(X, train_labels)

68.5 5. The Hashing Trick

68.5.1 5.1 Vocabularies do not scale

The vectorizers above must build and store an explicit mapping from each term to a column index. For a streaming corpus or a vocabulary in the tens of millions, this dictionary becomes a memory and engineering bottleneck. It must be learned in a first pass, held in RAM, serialized, and kept consistent between training and serving. The hashing trick eliminates the dictionary entirely.

68.5.2 5.2 Mechanism

Feature hashing maps each token directly to a column index by applying a hash function \(h\) and reducing modulo a fixed dimension \(m\):

\[ j = h(t) \bmod m. \]

The token’s contribution is added to column \(j\). To keep the expected inner product unbiased under collisions, a second hash \(\xi(t) \in \{-1, +1\}\) supplies a sign, so the hashed feature is

\[ \phi_j(d) = \sum_{t \in d \,:\, h(t) \bmod m = j} \xi(t)\,\text{count}(t, d). \]

The sign hash is what makes this work. Without it, two colliding terms would always add constructively, systematically inflating the inner product between documents that happen to share a collision. With independent random signs, a collision contributes a zero mean perturbation, so the estimate stays unbiased: for any two documents \(\mathbf{x}\) and \(\mathbf{y}\), the hashed dot product satisfies \(\mathbb{E}[\langle \phi(\mathbf{x}), \phi(\mathbf{y}) \rangle] = \langle \mathbf{x}, \mathbf{y} \rangle\), where the expectation is over the random choice of hash functions (reference 4). The price of an unbiased estimate is variance. The error variance from collisions scales as roughly \(\lVert \mathbf{x} \rVert^2 \lVert \mathbf{y} \rVert^2 / m\), so it falls linearly in the table size \(m\). Choosing \(m\) generously, for example \(2^{20}\) or \(2^{22}\), drives the collision noise far below the signal for typical sparse text vectors, since each document touches only a tiny fraction of the \(m\) buckets.

68.5.3 5.3 Trade-offs

The hashing trick is stateless, single pass, fixed memory, and trivially parallel, which makes it ideal for online learning and very large scale pipelines. The cost is interpretability: two distinct terms can collide into the same column, and there is no inverse map from a column back to a word, so feature inspection and debugging become harder. IDF weighting is also awkward because document frequencies are not tracked, though approximate schemes exist. In practice the hashing trick is chosen when scale and statelessness dominate and interpretability is expendable.

68.6 6. Bridge to Embeddings

68.6.1 6.1 The fundamental limitation of sparse features

Every representation so far treats words as atomic and orthogonal. In the BoW space the vectors for physician and doctor are exactly as dissimilar as physician and banana, because each word is its own dimension with no shared structure. This is the curse of one hot encoding: there is no notion of semantic proximity, and a model that has learned about doctor transfers nothing to physician. Synonymy, polysemy, and graded similarity are all invisible.

68.6.2 6.2 Distributional semantics

The escape route is the distributional hypothesis: words that occur in similar contexts tend to have similar meanings. If we represent a word by the statistics of the contexts it appears in, then physician and doctor, which keep similar company, end up with similar representations. Word embeddings operationalize this by mapping each word to a dense, low dimensional vector \(\mathbf{v}_w \in \mathbb{R}^k\) with \(k\) typically between 50 and 300, learned so that the geometry of the space reflects co occurrence statistics.

Methods such as word2vec learn these vectors by training a shallow network to predict a word from its context (or vice versa), while GloVe factorizes a global co occurrence matrix. The famous result is that the resulting space supports analogical arithmetic, where

\[ \mathbf{v}_{\text{king}} - \mathbf{v}_{\text{man}} + \mathbf{v}_{\text{woman}} \approx \mathbf{v}_{\text{queen}}, \]

evidence that linear directions in the space encode interpretable semantic relations such as gender or pluralization. Crucially, these dense vectors are low dimensional and continuous, so a model can generalize across related words rather than memorizing each one.

68.6.3 6.3 From words to documents and sentences

Word vectors describe words, but most tasks need a representation of a whole document or sentence. The simplest bridge averages the word vectors in a text, optionally weighting each by its IDF so that informative words dominate:

\[ \mathbf{v}_d = \frac{1}{\sum_{t \in d} \text{idf}(t)} \sum_{t \in d} \text{idf}(t)\,\mathbf{v}_t. \]

This averaged embedding is a strong and cheap document feature, but it again discards order and cannot disambiguate words whose meaning depends on context. Contextual sentence embeddings, produced by transformer encoders such as those in the Sentence-BERT family, address both issues. They feed the entire sentence through a network so that each token’s vector depends on its neighbors, then pool into a single fixed length vector tuned so that semantically similar sentences land near each other under cosine similarity. The output is a dense embedding suitable for semantic search, clustering, retrieval, and as input features to a downstream classifier.

The conceptual arc is therefore continuous. BoW is a sparse, exact, order free count vector. TF-IDF reweights it. Averaged word embeddings replace sparse counts with dense semantics but keep the bag assumption. Sentence embeddings restore context and order through a learned encoder. Each step trades interpretability and cost for semantic generalization.

68.7 7. When Classical Features Still Win

68.7.1 7.1 The honest comparison

It is tempting to assume neural embeddings dominate everywhere, but the evidence is more nuanced, and several regimes favor the classical pipeline.

Linear models over TF-IDF n-gram features are exceptionally strong on topic and keyword driven tasks: spam filtering, language identification, document routing, tagging, and many sentiment and intent classification problems. When the decisive signal is the presence of specific words or phrases, sparse features capture it directly and a linear model exploits it with no risk of underfitting the lexical cues. On standard topic classification benchmarks, a well tuned linear TF-IDF model is frequently within a small margin of a fine tuned transformer at a tiny fraction of the cost.

68.7.2 7.2 Cost, latency, and operations

Classical features win decisively on operational metrics. A TF-IDF plus linear model trains in seconds on a single CPU, serves predictions in microseconds, requires no GPU, has a memory footprint measured in megabytes, and produces coefficients an analyst can read to explain any decision. A transformer embedding pipeline demands accelerators, has higher per request latency, and is far harder to audit. In regulated domains where every decision must be explained, or in high throughput systems where latency and cost are binding constraints, the sparse linear model is often the responsible engineering choice.

68.7.3 7.3 Data, domain, and robustness

Embeddings shine when labeled data is scarce, because pretrained representations transfer knowledge from massive unlabeled corpora. But when labeled data is plentiful and in domain, the advantage narrows, since a linear model has enough signal to learn the task directly. Classical features also resist certain failure modes: they never hallucinate similarity, their behavior on a novel input is mechanically predictable, and they have no opaque dependence on pretraining data whose distribution may not match the deployment domain. For short, specialized, or highly technical vocabularies where general purpose embeddings were undertrained, character n-grams and TF-IDF can outperform off the shelf semantic vectors.

68.7.4 7.4 A practical decision rule

The mature workflow is not to choose ideologically but to layer. Always build the TF-IDF linear baseline first, because it is cheap and sets the bar. Reach for embeddings when the task requires semantic generalization beyond surface tokens, when synonymy and paraphrase matter, when labeled data is limited, or when the baseline plateaus below the required accuracy. Often the best production system concatenates both, sparse lexical features for precise keyword signal and dense embeddings for semantic coverage, giving the downstream model the strengths of each. Feature engineering for text did not end with the rise of embeddings; it absorbed them into a richer toolbox.

68.7.5 7.5 Common pitfalls

A handful of mistakes recur often enough to enumerate explicitly.

  • Fitting the vectorizer on the full dataset before splitting. The vocabulary and the IDF weights are learned parameters. Computing them over the test set leaks information and inflates reported accuracy. Fit the vectorizer on the training fold only, then transform the validation and test folds with the fitted state.
  • Treating tokenization as throwaway preprocessing. As noted in Section 1.1, any mismatch between training time and serving time normalization silently degrades quality. Serialize the whole pipeline, not just the model weights.
  • Over normalizing. Aggressive stemming, stop word removal, and case folding can erase the exact signal a task depends on, such as the negation in sentiment or function word frequencies in authorship attribution. Tune normalization with cross validation rather than applying it reflexively.
  • Unbounded n-gram ranges. Setting a wide ngram_range without min_df pruning produces a feature matrix with millions of columns, most occurring once, which invites overfitting and exhausts memory. Pair n-grams with frequency pruning.
  • Forgetting L2 normalization. Without it, long documents have larger vector norms and dominate distance and similarity computations purely because of length. Normalize unless you have a specific reason not to.
  • Expecting averaged embeddings to capture order. Mean pooling word vectors discards word order just as BoW does, so it cannot distinguish dog bites man from man bites dog. When order or compositional meaning is essential, use a contextual sentence encoder rather than an average.

68.8 8. Case Study: LLM-Induced Feature Spaces

Every representation in this chapter engineers features from the surface of text: which tokens appear, how often, in what local order, or where they sit in a pretrained embedding space. A 2026 study of AI-generated fiction demonstrates a third route with no classical equivalent: use LLMs to induce a compact, human-readable feature space that describes what a text does (its narrative decisions) rather than which words it contains, then hand those features to exactly the classical toolkit this chapter has been building: mixed-type encoding, gradient-boosted trees, and per-feature attribution (Russell et al. 2026). The study, STORYSCOPE, is worth a close look both for its findings and because it is a complete, replicable template for LLM-driven feature engineering, with code and data released under an open license.

68.8.1 8.1 The task: detect AI fiction without reading its style

Stylistic tells of AI text (overused words, characteristic punctuation, sentence rhythm) are highly discriminative but fleeting: vendors patch them, and fine-tuning to mimic human style has been shown to drop creative-writing detection rates from 97% to 3%. StoryScope therefore asks whether the narrative choices underlying a story (who has agency, how time flows, how explicitly themes are stated) separate human from AI fiction even when all stylistic signal is withheld.

The corpus is a parallel design: 10,272 human-written short stories are extracted from the Books3 corpus, a writing prompt is reverse-engineered from each with Gemini 2.5 Flash, and then five frontier models (Claude Sonnet 4.6, GPT 5.4, Gemini 3 Flash, DeepSeek V3.2, and Kimi K2.5) each write a story from the same prompt. That yields 61,608 stories averaging 4,753 words across six sources (the human author plus five models), all telling comparable premises, generated for a total API cost of about $4.4k.

68.8.2 8.2 A five-stage induction pipeline

Manually annotating narrative decisions across 60k long stories is infeasible, so the feature space itself is induced by LLMs, grounded in the ten-dimension NarraBench taxonomy of narrative structure (agent, social network, event, plot, structure, setting, time, revelation, perspective, and style) (Hamilton, Wilkens, and Piper 2025):

  1. Structured templates. GPT-5.1 converts each story into a JSON template organized along the ten dimensions (character names, roles, and motivations for agent; causal chains and key events for event; and so on). The template is a controlled intermediate representation: downstream stages reason over narrative content, not prose.
  2. Cross-source comparison. For a held-out discovery pool of 600 stories over 100 prompts, GPT-5.1 reads all six templates per prompt and writes a structured comparative analysis of where the sources diverge. This stage compresses roughly 2.7M tokens of raw text into about 686K tokens of observations.
  3. Feature discovery. Ten dimension-specific expert prompts ask GPT-5.1 to propose discriminative features as closed-form questions with discrete answers. Three discovery runs yield 408 candidates, deduplicated by embedding clustering (cosine threshold 0.85), leaving \(d = 304\) features in five response types: categorical (124), ordinal (59), scale (45), binary (44), and multi-select (32).
  4. Feature assignment. Gemini 3 Flash annotates every story with all 304 features. Assignment is reliable: repeatability across five independent runs reaches Krippendorff’s \(\alpha = 0.88\), and agreement with human annotators on a 240-feature subset averages Cohen’s \(\kappa = 0.84\).
  5. Classification and attribution. XGBoost classifiers (Chen and Guestrin 2016) are trained on the encoded features, and SHAP (Lundberg and Lee 2017) decomposes every prediction into per-feature contributions.

The design choice worth internalizing is the middle of the pipeline: instead of asking one model to simultaneously read, compare, and formalize, each stage consumes the previous stage’s compressed artifact. That is what makes an interpretable feature space inducible at corpus scale.

68.8.3 8.3 Encoding a mixed-type feature vector

The annotation stage yields a typed semantic vector \(z = (z_1, \dots, z_d)\) per story. The classifier does not consume \(z\) directly; each feature is encoded according to its type,

\[ \phi_j(z_j) = \begin{cases} \operatorname{onehot}(z_j) \in \{0,1\}^{|V_j|} & \text{categorical with option set } V_j \\ \operatorname{multihot}(z_j) \in \{0,1\}^{|V_j|} & \text{multi-select} \\ z_j \in \{1, \dots, K_j\} & \text{ordinal and scale, kept numeric} \\ z_j \in \{0, 1\} & \text{binary} \end{cases} \]

and the encoded blocks are concatenated into \(x = [\phi_1(z_1) \,\|\, \cdots \,\|\, \phi_d(z_d)] \in \mathbb{R}^D\). For the full 304-feature set \(D = 1{,}108\); the narrative-only variant (257 features, all style features removed) has \(D = 958\); the style-only variant (39 features) has \(D = 129\). Splits are grouped at the prompt level (7,383 train, 1,405 validation, and 1,384 test prompts) so that no premise straddles train and test, the same leakage discipline as Section 7.5’s rule about fitting vectorizers on the training fold only, applied one level up.

68.8.5 8.5 From SHAP to feature roles: core and fingerprint

The paper’s post-hoc analysis is a model of disciplined feature selection. Importance and stability are assessed by bootstrap SHAP analysis: \(B = 50\) prompt-level resampling iterations of the binary task, giving each feature \(j\) a mean absolute SHAP importance \(\bar{s}_j\), a bootstrap stability score \(\operatorname{stab}_j\), a top-25 rate \(\operatorname{top25}_j\) (how often the feature ranks among the 25 most important across iterations), and a permutation \(p\)-value \(p_j\) against a shuffled-label null. A feature is important if \(\bar{s}_j\) exceeds the top quartile of importances, and stable-important if its stability is at least the median among important features and its importance beats the 95th-percentile null with \(p_j \le 0.10\). A core feature must clear all of that plus three magnitude thresholds:

\[ j \in \text{Core} \iff \text{stable-important}(j) \,\wedge\, \operatorname{stab}_j \ge 0.55 \,\wedge\, \operatorname{top25}_j \ge 0.60 \,\wedge\, |\Delta_j| \ge 0.20 \,\wedge\, \sigma_j^{\text{AI}} \le 0.35, \]

where \(\Delta_j\) is the human-AI gap in mean encoded value and \(\sigma_j^{\text{AI}}\) is the spread of that mean across the five AI models (a core feature must separate humans from all models consistently, not from one). This yields 30 core features. Fingerprint features come from the six-way task instead: a feature qualifies when its SHAP importance concentrates in a single source class and that source’s values visibly differ, yielding 75 fingerprint features, distributed very unevenly (human 32, Claude 26, GPT 11, Gemini 11, DeepSeek 7, Kimi 3).

The core features read like an editor’s checklist of AI habits. AI stories over-explain themes (narrators state the moral 77% of the time versus 52% for humans), use dialogue for philosophical debate (59% vs. 34%), avoid subplots (79% subplot-free vs. 57%), resolve through protagonist choice (69% vs. 46%), and render emotion through bodies and senses (embodied emotion 81% vs. 38%, smell imagery 82% vs. 57%, explicit emotion labels only 8% vs. 29%). Human authors name real texts and authors (47% vs. 24%), break the fourth wall (67% vs. 39%), address the reader (28% vs. 7%), and write morally ambivalent protagonists (59% vs. 38%). The fingerprints are just as legible: Claude escalates events the least and favors epilogues over dream sequences, GPT over-indexes on gossip as a plot mechanism (64%) and on subverted expectations (41%), Gemini writes the tidiest endings and the bleakest settings (88% tagged bleak), DeepSeek front-loads crucial context, and Kimi sits at the generic center of the AI distribution with the fewest fingerprints and the lowest attribution F1.

68.8.6 8.6 A miniature StoryScope

The pipeline’s downstream half fits in one code cell. The simulation below generates a parallel corpus in which each source’s feature marginals are taken from the paper where reported (the core rates above, the fingerprint rates for GPT, Claude, and Gemini) and set to plausible illustrative values where the paper is qualitative, adds annotation noise consistent with the reported human-model agreement, then runs the paper’s exact recipe: mixed-type encoding, a prompt-grouped split, XGBoost for binary detection and six-way attribution, and TreeSHAP importances straight from XGBoost’s pred_contribs (no extra library needed).

import numpy as np
import pandas as pd
import xgboost as xgb
from sklearn.metrics import f1_score
from sklearn.model_selection import GroupShuffleSplit

rng = np.random.default_rng(7)

SOURCES = ["human", "claude", "gpt", "gemini", "deepseek", "kimi"]
N_PROMPTS = 1000

# Core-style binary features as (human rate, shared AI rate). Every pair is a
# marginal reported in the paper (sections 4.1 and 5).
CORE_RATES = {
    "narrator_explains_theme": (0.52, 0.77),
    "dialogue_as_philosophy":  (0.34, 0.59),
    "no_subplots":             (0.57, 0.79),
    "protagonist_resolution":  (0.46, 0.69),
    "olfactory_imagery":       (0.57, 0.82),
    "named_reference":         (0.47, 0.24),
    "addresses_reader":        (0.28, 0.07),
    "breaks_fourth_wall":      (0.67, 0.39),
    "ambivalent_protagonist":  (0.59, 0.38),
    "vague_allusions_only":    (0.50, 0.72),
    "balanced_reference_mix":  (0.37, 0.16),
    "subplots_serve_theme":    (0.42, 0.21),
    "acceptance_resolution":   (0.27, 0.47),
}

# One categorical feature: dominant mode of emotional expression. The explicit
# (29% vs 8%) and embodied (38% vs 81%) rates are the paper's; the remainder
# goes to behavioral cues.
EMOTION_LEVELS = ["explicit_label", "embodied", "behavioral"]
EMOTION_P = {"human": [0.29, 0.38, 0.33], "ai": [0.08, 0.81, 0.11]}

# 1-5 scale features as (human mean, AI mean). The explicitness pair is the
# paper's moral/philosophical weighting means (3.26 vs 3.68); the discontinuity
# gap is illustrative, direction only (humans jump across time more).
SCALE_MEANS = {
    "thematic_explicitness":       (3.26, 3.68),
    "chronological_discontinuity": (2.90, 2.30),
}

# Fingerprint features: a shared default rate plus per-model overrides. GPT's
# gossip (64%) and subversion (41%), Claude's continuism (62%), and Gemini's
# bleak settings (88%) are reported values; the defaults, the dream and
# epilogue rates, and the DeepSeek front-loading override are illustrative.
# Kimi deliberately gets no override, matching its 'generic center of the AI
# distribution' role in the paper.
FP_BASE = {
    "gossip_mechanism":      0.50,
    "subverts_expectations": 0.32,
    "continuist_tradition":  0.47,
    "bleak_setting":         0.55,
    "frontloads_context":    0.40,
    "dream_sequence":        0.10,
    "writes_epilogue":       0.30,
    "extended_denouement":   0.35,
}
FP_OVERRIDES = {
    "gpt":      {"gossip_mechanism": 0.64, "subverts_expectations": 0.41,
                 "dream_sequence": 0.30},
    "claude":   {"continuist_tradition": 0.62, "writes_epilogue": 0.55,
                 "dream_sequence": 0.03},
    "gemini":   {"bleak_setting": 0.88, "extended_denouement": 0.60},
    "deepseek": {"frontloads_context": 0.70},
}
# Claude's 'notably flat event escalation' as an illustrative scale gap.
ESCALATION_MEAN = {"claude": 2.1}
ESCALATION_DEFAULT = 3.0

ANNOTATION_FLIP = 0.02  # imperfect LLM annotation (human-model kappa is 0.84)

rows = []
for prompt in range(N_PROMPTS):
    for src in SOURCES:
        is_ai = src != "human"
        row = {"prompt": prompt, "source": src}
        for name, (h, a) in CORE_RATES.items():
            row[name] = rng.random() < (a if is_ai else h)
        row["emotion_mode"] = EMOTION_LEVELS[
            rng.choice(3, p=EMOTION_P["ai" if is_ai else "human"])
        ]
        for name, (h, a) in SCALE_MEANS.items():
            row[name] = int(np.clip(round(rng.normal(a if is_ai else h, 0.8)), 1, 5))
        for name, base in FP_BASE.items():
            row[name] = rng.random() < FP_OVERRIDES.get(src, {}).get(name, base)
        row["event_escalation"] = int(
            np.clip(round(rng.normal(ESCALATION_MEAN.get(src, ESCALATION_DEFAULT), 0.8)), 1, 5)
        )
        for name in list(CORE_RATES) + list(FP_BASE):
            if rng.random() < ANNOTATION_FLIP:
                row[name] = not row[name]
        rows.append(row)

df = pd.DataFrame(rows)

# Encode exactly as the paper does: one-hot for categorical, numeric for
# ordinal/scale, binary as-is.
X = pd.get_dummies(df.drop(columns=["prompt", "source"]),
                   columns=["emotion_mode"]).astype(float)
groups = df["prompt"].to_numpy()

# Prompt-level grouped split so no prompt straddles train and test.
train_idx, test_idx = next(
    GroupShuffleSplit(n_splits=1, test_size=0.25, random_state=0).split(X, groups=groups)
)

# Binary detection: human is the positive minority class at a 1:5 ratio, so we
# weight it 5x as the paper does.
y_bin = (df["source"] == "human").astype(int).to_numpy()
clf_bin = xgb.XGBClassifier(n_estimators=300, max_depth=6, learning_rate=0.1,
                            reg_lambda=2.0, scale_pos_weight=5.0,
                            eval_metric="logloss", random_state=0)
clf_bin.fit(X.iloc[train_idx], y_bin[train_idx])
f1_b = f1_score(y_bin[test_idx], clf_bin.predict(X.iloc[test_idx]), average="macro")

# Six-way attribution with the same features.
codes = {s: i for i, s in enumerate(SOURCES)}
y_six = df["source"].map(codes).to_numpy()
clf_six = xgb.XGBClassifier(n_estimators=300, max_depth=6, learning_rate=0.1,
                            reg_lambda=1.0, eval_metric="mlogloss", random_state=0)
clf_six.fit(X.iloc[train_idx], y_six[train_idx])
pred_six = clf_six.predict(X.iloc[test_idx])
f1_s = f1_score(y_six[test_idx], pred_six, average="macro")
per_class = f1_score(y_six[test_idx], pred_six, average=None)

print(f"binary human-vs-AI macro-F1:   {f1_b:.3f}"
      "   (paper: 0.932 with 257 features, 0.848 with the 30 core)")
print(f"six-way attribution macro-F1:  {f1_s:.3f}"
      "   (paper: 0.684 with 257 features, 0.465 with the 30 core)\n")
print("per-source F1 (paper ordering: human > Claude > GPT >> Gemini/DeepSeek/Kimi):")
for s in np.argsort(per_class)[::-1]:
    print(f"  {SOURCES[s]:<9} {per_class[s]:.3f}")

# SHAP via XGBoost's built-in TreeSHAP (pred_contribs), no extra library needed.
dtest = xgb.DMatrix(X.iloc[test_idx])
contrib_bin = clf_bin.get_booster().predict(dtest, pred_contribs=True)[:, :-1]
imp = np.abs(contrib_bin).mean(axis=0)
top = np.argsort(imp)[::-1][:6]
print("\ntop core features by mean |SHAP| (binary task):")
for j in top:
    print(f"  {X.columns[j]:<28} {imp[j]:.3f}")

# Multiclass SHAP: (n, classes, D+1). A fingerprint feature is one whose
# importance concentrates in a single source class.
contrib_six = clf_six.get_booster().predict(dtest, pred_contribs=True)[:, :, :-1]
imp_six = np.abs(contrib_six).mean(axis=0)
print("\ntop fingerprint feature per AI source (multiclass SHAP):")
for s in SOURCES[1:]:
    k = codes[s]
    j = int(np.argmax(imp_six[k]))
    print(f"  {s:<9} -> {X.columns[j]:<28} {imp_six[k, j]:.3f}")

# Feature Engineering for Text

Text is the most abundant and least structured data modality in modern machine learning. A document is a sequence of characters with no fixed length, no inherent numeric meaning, and no obvious alignment between examples. Before any statistical learner can operate on text, that sequence must be transformed into a finite vector of features. This transformation is the subject of feature engineering for text, and despite the dominance of large neural language models, the classical pipeline remains indispensable. It is fast, interpretable, cheap to deploy, and frequently competitive on the tasks that actually fill production backlogs.

This chapter develops the classical text feature pipeline from first principles: tokenization, bag of words, n-grams, term weighting with TF-IDF, and the hashing trick for scale. It then builds a bridge to distributed representations, word and sentence embeddings, and gives a sober account of when sparse classical features still outperform dense neural ones. It closes with a modern case study in which the feature space itself is induced by LLMs.

The pipeline is best understood as a sequence of maps from one representation to the next, each adding structure or shedding cost.

```{mermaid}
flowchart LR
    A["Raw text string"] --> B["Tokens"]
    B --> C["Normalized tokens"]
    C --> D["Document term matrix"]
    D --> E["TF-IDF weighted matrix"]
    C --> F["Hashed feature vector"]
    C --> G["Averaged word embedding"]
    A --> H["Sentence embedding"]
    E --> I["Linear classifier"]
    F --> I
    G --> I
    H --> I
```

The top path is the sparse symbolic pipeline that dominates Sections 1 through 5. The lower paths are the dense semantic routes of Section 6. Section 7 explains when each is the right choice, and Section 8 studies a third route absent from this diagram entirely: feature spaces induced by LLMs.

## 1. From Characters to Tokens

### 1.1 The tokenization problem

A learner cannot consume raw bytes meaningfully, so the first step is to segment a string into discrete units called tokens. Tokenization sounds trivial in English, where whitespace approximates word boundaries, but it is full of decisions that materially affect downstream accuracy. Consider the string `"Don't email me at jane.doe@acme.co!"`. Should `Don't` be one token, two (`Do` and `n't`), or three? Is `jane.doe@acme.co` a single semantic unit or five fragments? Each choice changes the feature space.

A simple regular expression tokenizer captures most word like spans:

```python
import re
def tokenize(text):
    return re.findall(r"[A-Za-z0-9']+", text.lower())
```

This lowercases, splits on non alphanumeric characters, and keeps apostrophes. It is crude but reproducible, and reproducibility matters more than linguistic elegance because the same function must run at training and inference time. A subtle but consequential rule follows from this: the tokenizer and every normalization step are part of the model, not preprocessing performed once and discarded. Any divergence between the function applied to training data and the function applied at serving time is a silent source of degradation often called training serving skew, and the most reliable defense is to encapsulate the entire transform (in scikit-learn, a `Pipeline`) so that it is fit once and applied identically thereafter.

To fix vocabulary, define the **type token distinction**. A token is a single occurrence of a unit in a specific document, while a type is a distinct unit in the abstract vocabulary. The sentence `the cat sat on the mat` has six tokens but five types, since `the` occurs twice. The vocabulary is the set of types, and the dimension of the feature space is the number of types retained after pruning.

### 1.2 Normalization choices

Beyond segmentation, several normalization steps shrink the vocabulary and improve generalization. Lowercasing collapses `The` and `the`. Stemming reduces inflected forms to a root, so `running`, `runs`, and `ran` may all map toward `run` using a rule based algorithm such as the Porter stemmer. Lemmatization does the same but uses a dictionary and part of speech information to produce valid words, mapping `better` to `good`. Accent folding and Unicode normalization (NFKC) unify visually identical characters.

Each normalization trades precision for recall in the feature space. Aggressive stemming can merge `university` and `universe`, destroying a useful distinction. The right level of normalization is empirical and task dependent, and it should be tuned with cross validation rather than assumed.

### 1.3 Stop words and pruning

Function words such as `the`, `of`, and `is` occur in nearly every document and carry little discriminative signal for many tasks. Removing a stop word list reduces dimensionality and noise. However, stop word removal is not universally beneficial. For sentiment, the word `not` is decisive, and for authorship attribution function word frequencies are among the strongest signals. Modern practice often retains stop words and lets the weighting scheme downweight them, which is more robust than a hard list.

A related lever is frequency pruning. Tokens appearing in fewer than `min_df` documents are likely typos or noise, and tokens in more than `max_df` fraction of documents behave like stop words. Pruning both tails keeps the vocabulary compact and the model well conditioned. The shape of the count distribution makes this pruning especially effective. Word frequencies in natural language follow Zipf's law: ranking types by frequency, the frequency of the type at rank $r$ is approximately

$$
f(r) \approx \frac{C}{r^{s}}, \qquad s \approx 1,
$$

so a small number of types account for most tokens while a long tail of types each occur once or twice. The long tail inflates dimensionality without adding usable signal, which is exactly why a modest `min_df` (say 5) can discard the majority of types while removing only a small fraction of total token mass.

## 2. The Bag of Words Model

### 2.1 Vector space representation

The bag of words (BoW) model represents a document as the multiset of its tokens, discarding order entirely. Given a vocabulary $V = \{w_1, \dots, w_{|V|}\}$ extracted from the training corpus, a document $d$ becomes a vector $\mathbf{x}_d \in \mathbb{R}^{|V|}$ whose $j$th entry is the count of term $w_j$ in $d$:

$$
x_{d,j} = \text{tf}(w_j, d) = \sum_{t \in d} \mathbb{1}[t = w_j].
$$

Stacking all document vectors row wise yields the document term matrix $X \in \mathbb{R}^{n \times |V|}$. This matrix is the central object of classical text mining. It is extremely sparse, since any single document uses a tiny fraction of the global vocabulary, so it is stored in compressed sparse row format and the model never materializes the zeros.

### 2.2 Why discarding order can work

Throwing away word order seems reckless, yet BoW is a strong baseline for topic level tasks such as spam detection, document categorization, and many sentiment problems. The reason is that for these tasks the presence of certain words is nearly sufficient: an email containing `viagra`, `wire transfer`, and `urgent` is probably spam regardless of arrangement. The signal lives in the marginal token statistics, which BoW captures exactly. Tasks that hinge on syntax or compositional meaning, such as `the food was good but the service was not`, are where BoW begins to fail, and the next section partially repairs this.

The bag of words assumption has a precise probabilistic reading. The multinomial naive Bayes classifier models a document of class $c$ as a sequence of independent draws from a class conditional word distribution, giving

$$
P(d \mid c) = \frac{(\sum_j x_{d,j})!}{\prod_j x_{d,j}!} \prod_{j} P(w_j \mid c)^{x_{d,j}}.
$$

The independence of draws is exactly the discarding of order, and the log likelihood is linear in the count vector $\mathbf{x}_d$. This is why a linear classifier over BoW features is not an arbitrary choice but the natural decision rule under the bag assumption: maximizing the posterior reduces to a weighted sum of token counts plus a bias, which is precisely what logistic regression and the linear SVM also compute, learned discriminatively rather than generatively.

### 2.3 Geometry and similarity

Once documents are vectors, similarity becomes geometry. The dominant measure is cosine similarity, which compares orientation rather than magnitude and so is robust to document length:

$$
\cos(\mathbf{x}, \mathbf{y}) = \frac{\mathbf{x} \cdot \mathbf{y}}{\lVert \mathbf{x} \rVert \, \lVert \mathbf{y} \rVert}.
$$

Cosine similarity on BoW or TF-IDF vectors underlies classical search ranking, nearest neighbor classification, and clustering. Its interpretability, every nonzero dimension corresponds to a literal word, is a property that dense embeddings sacrifice.

## 3. N-grams and Local Order

### 3.1 Capturing short phrases

A bigram is an ordered pair of adjacent tokens, a trigram an ordered triple, and in general an n-gram is a contiguous window of $n$ tokens. By adding n-grams to the vocabulary, the BoW model recovers a limited but valuable amount of word order. The phrase `not good` becomes a single feature distinct from `good`, allowing a linear model to assign it negative weight. For the sentence `New York is not Los Angeles`, the bigrams `new york` and `los angeles` capture multiword entities that unigrams shatter.

### 3.2 The dimensionality cost

N-grams are powerful but expensive. If the unigram vocabulary has size $|V|$, the space of possible bigrams is $|V|^2$, and trigrams $|V|^3$. In practice most n-grams never occur, so the realized count grows roughly linearly with corpus size rather than combinatorially, but the feature matrix still explodes from tens of thousands of columns to millions. This drives memory pressure and overfitting risk, and it is the primary motivation for the hashing trick in Section 5.

A common compromise is to include unigrams and bigrams (`ngram_range=(1,2)`) with aggressive `min_df` pruning, which captures the highest value local order while keeping the vocabulary manageable.

### 3.3 Character n-grams

N-grams need not be over words. Character n-grams, contiguous spans of characters, are remarkably robust. The word `engineering` yields character 4-grams `engi`, `ngin`, `gine`, and so on. Because they share substrings, character n-grams handle misspellings, morphological variation, and out of vocabulary words gracefully, and they require no language specific tokenizer. They are the workhorse of language identification, authorship attribution, and noisy social media text, and they are the conceptual ancestor of subword tokenization in neural models.

## 4. Term Weighting with TF-IDF

### 4.1 The intuition

Raw counts overweight common words. A term appearing in every document discriminates nothing, while a rare term that appears in only a handful of documents is highly informative when it does. TF-IDF (term frequency times inverse document frequency) formalizes this by scaling each count by how surprising the term is across the corpus.

### 4.2 The formulas

The term frequency component measures local importance. A common variant uses sublinear scaling to dampen the effect of repetition:

$$
\text{tf}(t, d) = 1 + \log\big(\text{count}(t, d)\big) \quad \text{for } \text{count}(t,d) > 0.
$$

The inverse document frequency component measures global rarity. Let $n$ be the number of documents and $\text{df}(t)$ the number containing term $t$. A standard smoothed form is

$$
\text{idf}(t) = \log\frac{1 + n}{1 + \text{df}(t)} + 1.
$$

The TF-IDF weight is the product, and the resulting document vector is usually L2 normalized so that document length does not dominate:

$$
\text{tfidf}(t, d) = \text{tf}(t, d) \cdot \text{idf}(t), \qquad \hat{\mathbf{x}}_d = \frac{\mathbf{x}_d}{\lVert \mathbf{x}_d \rVert_2}.
$$

The smoothing constants prevent division by zero and bound the IDF of terms absent from training. The logarithm in IDF reflects a diminishing returns view of rarity, consistent with an information theoretic reading where $\text{idf}(t)$ approximates the self information of observing term $t$ in a randomly drawn document. If $P(t)$ is the probability that a random document contains $t$, estimated by $\text{df}(t)/n$, then the unsmoothed IDF $\log\frac{n}{\text{df}(t)} = -\log P(t)$ is exactly the Shannon surprisal of the event that $t$ appears. A term that occurs everywhere carries near zero surprisal and is heavily downweighted, while a term confined to a few documents carries high surprisal and is amplified. This is the formal sense in which TF-IDF measures specificity, as Sparck Jones argued in the founding paper on the idea (reference 3).

### 4.3 A worked example

Take a toy corpus of four documents over the terms `cat`, `dog`, and `the`.

| Document | cat | dog | the |
|----------|-----|-----|-----|
| $d_1$    | 2   | 0   | 3   |
| $d_2$    | 0   | 1   | 2   |
| $d_3$    | 1   | 1   | 1   |
| $d_4$    | 0   | 0   | 4   |

Here $n = 4$. The document frequencies are $\text{df}(\text{cat}) = 2$, $\text{df}(\text{dog}) = 2$, and $\text{df}(\text{the}) = 4$. Using the smoothed form $\text{idf}(t) = \log\frac{1+n}{1+\text{df}(t)} + 1$ with natural logarithm,

$$
\text{idf}(\text{cat}) = \log\tfrac{5}{3} + 1 \approx 1.51, \quad
\text{idf}(\text{dog}) = \log\tfrac{5}{3} + 1 \approx 1.51, \quad
\text{idf}(\text{the}) = \log\tfrac{5}{5} + 1 = 1.00.
$$

The term `the`, present in every document, receives the floor weight of 1, while the rarer `cat` and `dog` are boosted. For document $d_3$ with raw counts $(1, 1, 1)$ and sublinear term frequency $1 + \log(1) = 1$ for each, the unnormalized TF-IDF vector is $(1.51,\ 1.51,\ 1.00)$. L2 normalization divides by $\sqrt{1.51^2 + 1.51^2 + 1.00^2} \approx 2.34$, giving the final vector $(0.645,\ 0.645,\ 0.427)$. The common word `the` survives but is muted, and the two content words dominate the document's direction in the vector space, which is exactly the behavior cosine similarity then exploits.

### 4.4 Why it remains a strong baseline

TF-IDF weighted vectors fed to a linear classifier such as logistic regression or a linear support vector machine form one of the most reliable baselines in applied natural language processing. The weighting is parameter free, the model is convex and trains in seconds on millions of documents, and the learned coefficients are directly inspectable. Before reaching for a transformer, a practitioner should establish this baseline, because surprisingly often it is within a point or two of far more expensive models, and it is the number every fancier method must beat.

```python
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
vec = TfidfVectorizer(ngram_range=(1,2), min_df=5, sublinear_tf=True)
X = vec.fit_transform(train_texts)
clf = LogisticRegression(max_iter=1000).fit(X, train_labels)
```

## 5. The Hashing Trick

### 5.1 Vocabularies do not scale

The vectorizers above must build and store an explicit mapping from each term to a column index. For a streaming corpus or a vocabulary in the tens of millions, this dictionary becomes a memory and engineering bottleneck. It must be learned in a first pass, held in RAM, serialized, and kept consistent between training and serving. The hashing trick eliminates the dictionary entirely.

### 5.2 Mechanism

Feature hashing maps each token directly to a column index by applying a hash function $h$ and reducing modulo a fixed dimension $m$:

$$
j = h(t) \bmod m.
$$

The token's contribution is added to column $j$. To keep the expected inner product unbiased under collisions, a second hash $\xi(t) \in \{-1, +1\}$ supplies a sign, so the hashed feature is

$$
\phi_j(d) = \sum_{t \in d \,:\, h(t) \bmod m = j} \xi(t)\,\text{count}(t, d).
$$

The sign hash is what makes this work. Without it, two colliding terms would always add constructively, systematically inflating the inner product between documents that happen to share a collision. With independent random signs, a collision contributes a zero mean perturbation, so the estimate stays unbiased: for any two documents $\mathbf{x}$ and $\mathbf{y}$, the hashed dot product satisfies $\mathbb{E}[\langle \phi(\mathbf{x}), \phi(\mathbf{y}) \rangle] = \langle \mathbf{x}, \mathbf{y} \rangle$, where the expectation is over the random choice of hash functions (reference 4). The price of an unbiased estimate is variance. The error variance from collisions scales as roughly $\lVert \mathbf{x} \rVert^2 \lVert \mathbf{y} \rVert^2 / m$, so it falls linearly in the table size $m$. Choosing $m$ generously, for example $2^{20}$ or $2^{22}$, drives the collision noise far below the signal for typical sparse text vectors, since each document touches only a tiny fraction of the $m$ buckets.

### 5.3 Trade-offs

The hashing trick is stateless, single pass, fixed memory, and trivially parallel, which makes it ideal for online learning and very large scale pipelines. The cost is interpretability: two distinct terms can collide into the same column, and there is no inverse map from a column back to a word, so feature inspection and debugging become harder. IDF weighting is also awkward because document frequencies are not tracked, though approximate schemes exist. In practice the hashing trick is chosen when scale and statelessness dominate and interpretability is expendable.

## 6. Bridge to Embeddings

### 6.1 The fundamental limitation of sparse features

Every representation so far treats words as atomic and orthogonal. In the BoW space the vectors for `physician` and `doctor` are exactly as dissimilar as `physician` and `banana`, because each word is its own dimension with no shared structure. This is the curse of one hot encoding: there is no notion of semantic proximity, and a model that has learned about `doctor` transfers nothing to `physician`. Synonymy, polysemy, and graded similarity are all invisible.

### 6.2 Distributional semantics

The escape route is the distributional hypothesis: words that occur in similar contexts tend to have similar meanings. If we represent a word by the statistics of the contexts it appears in, then `physician` and `doctor`, which keep similar company, end up with similar representations. Word embeddings operationalize this by mapping each word to a dense, low dimensional vector $\mathbf{v}_w \in \mathbb{R}^k$ with $k$ typically between 50 and 300, learned so that the geometry of the space reflects co occurrence statistics.

Methods such as word2vec learn these vectors by training a shallow network to predict a word from its context (or vice versa), while GloVe factorizes a global co occurrence matrix. The famous result is that the resulting space supports analogical arithmetic, where

$$
\mathbf{v}_{\text{king}} - \mathbf{v}_{\text{man}} + \mathbf{v}_{\text{woman}} \approx \mathbf{v}_{\text{queen}},
$$

evidence that linear directions in the space encode interpretable semantic relations such as gender or pluralization. Crucially, these dense vectors are low dimensional and continuous, so a model can generalize across related words rather than memorizing each one.

### 6.3 From words to documents and sentences

Word vectors describe words, but most tasks need a representation of a whole document or sentence. The simplest bridge averages the word vectors in a text, optionally weighting each by its IDF so that informative words dominate:

$$
\mathbf{v}_d = \frac{1}{\sum_{t \in d} \text{idf}(t)} \sum_{t \in d} \text{idf}(t)\,\mathbf{v}_t.
$$

This averaged embedding is a strong and cheap document feature, but it again discards order and cannot disambiguate words whose meaning depends on context. Contextual sentence embeddings, produced by transformer encoders such as those in the Sentence-BERT family, address both issues. They feed the entire sentence through a network so that each token's vector depends on its neighbors, then pool into a single fixed length vector tuned so that semantically similar sentences land near each other under cosine similarity. The output is a dense embedding suitable for semantic search, clustering, retrieval, and as input features to a downstream classifier.

The conceptual arc is therefore continuous. BoW is a sparse, exact, order free count vector. TF-IDF reweights it. Averaged word embeddings replace sparse counts with dense semantics but keep the bag assumption. Sentence embeddings restore context and order through a learned encoder. Each step trades interpretability and cost for semantic generalization.

## 7. When Classical Features Still Win

### 7.1 The honest comparison

It is tempting to assume neural embeddings dominate everywhere, but the evidence is more nuanced, and several regimes favor the classical pipeline.

Linear models over TF-IDF n-gram features are exceptionally strong on topic and keyword driven tasks: spam filtering, language identification, document routing, tagging, and many sentiment and intent classification problems. When the decisive signal is the presence of specific words or phrases, sparse features capture it directly and a linear model exploits it with no risk of underfitting the lexical cues. On standard topic classification benchmarks, a well tuned linear TF-IDF model is frequently within a small margin of a fine tuned transformer at a tiny fraction of the cost.

### 7.2 Cost, latency, and operations

Classical features win decisively on operational metrics. A TF-IDF plus linear model trains in seconds on a single CPU, serves predictions in microseconds, requires no GPU, has a memory footprint measured in megabytes, and produces coefficients an analyst can read to explain any decision. A transformer embedding pipeline demands accelerators, has higher per request latency, and is far harder to audit. In regulated domains where every decision must be explained, or in high throughput systems where latency and cost are binding constraints, the sparse linear model is often the responsible engineering choice.

### 7.3 Data, domain, and robustness

Embeddings shine when labeled data is scarce, because pretrained representations transfer knowledge from massive unlabeled corpora. But when labeled data is plentiful and in domain, the advantage narrows, since a linear model has enough signal to learn the task directly. Classical features also resist certain failure modes: they never hallucinate similarity, their behavior on a novel input is mechanically predictable, and they have no opaque dependence on pretraining data whose distribution may not match the deployment domain. For short, specialized, or highly technical vocabularies where general purpose embeddings were undertrained, character n-grams and TF-IDF can outperform off the shelf semantic vectors.

### 7.4 A practical decision rule

The mature workflow is not to choose ideologically but to layer. Always build the TF-IDF linear baseline first, because it is cheap and sets the bar. Reach for embeddings when the task requires semantic generalization beyond surface tokens, when synonymy and paraphrase matter, when labeled data is limited, or when the baseline plateaus below the required accuracy. Often the best production system concatenates both, sparse lexical features for precise keyword signal and dense embeddings for semantic coverage, giving the downstream model the strengths of each. Feature engineering for text did not end with the rise of embeddings; it absorbed them into a richer toolbox.

### 7.5 Common pitfalls

A handful of mistakes recur often enough to enumerate explicitly.

- **Fitting the vectorizer on the full dataset before splitting.** The vocabulary and the IDF weights are learned parameters. Computing them over the test set leaks information and inflates reported accuracy. Fit the vectorizer on the training fold only, then transform the validation and test folds with the fitted state.
- **Treating tokenization as throwaway preprocessing.** As noted in Section 1.1, any mismatch between training time and serving time normalization silently degrades quality. Serialize the whole pipeline, not just the model weights.
- **Over normalizing.** Aggressive stemming, stop word removal, and case folding can erase the exact signal a task depends on, such as the negation in sentiment or function word frequencies in authorship attribution. Tune normalization with cross validation rather than applying it reflexively.
- **Unbounded n-gram ranges.** Setting a wide `ngram_range` without `min_df` pruning produces a feature matrix with millions of columns, most occurring once, which invites overfitting and exhausts memory. Pair n-grams with frequency pruning.
- **Forgetting L2 normalization.** Without it, long documents have larger vector norms and dominate distance and similarity computations purely because of length. Normalize unless you have a specific reason not to.
- **Expecting averaged embeddings to capture order.** Mean pooling word vectors discards word order just as BoW does, so it cannot distinguish `dog bites man` from `man bites dog`. When order or compositional meaning is essential, use a contextual sentence encoder rather than an average.

## 8. Case Study: LLM-Induced Feature Spaces {#sec-llm-induced-features}

Every representation in this chapter engineers features from the surface of text: which tokens appear, how often, in what local order, or where they sit in a pretrained embedding space. A 2026 study of AI-generated fiction demonstrates a third route with no classical equivalent: use LLMs to *induce* a compact, human-readable feature space that describes what a text *does* (its narrative decisions) rather than which words it contains, then hand those features to exactly the classical toolkit this chapter has been building: mixed-type encoding, gradient-boosted trees, and per-feature attribution [@russell2026storyscope]. The study, STORYSCOPE, is worth a close look both for its findings and because it is a complete, replicable template for LLM-driven feature engineering, with code and data released under an open license.

### 8.1 The task: detect AI fiction without reading its style

Stylistic tells of AI text (overused words, characteristic punctuation, sentence rhythm) are highly discriminative but fleeting: vendors patch them, and fine-tuning to mimic human style has been shown to drop creative-writing detection rates from 97% to 3%. StoryScope therefore asks whether the *narrative choices* underlying a story (who has agency, how time flows, how explicitly themes are stated) separate human from AI fiction even when all stylistic signal is withheld.

The corpus is a parallel design: 10,272 human-written short stories are extracted from the Books3 corpus, a writing prompt is reverse-engineered from each with Gemini 2.5 Flash, and then five frontier models (Claude Sonnet 4.6, GPT 5.4, Gemini 3 Flash, DeepSeek V3.2, and Kimi K2.5) each write a story from the same prompt. That yields 61,608 stories averaging 4,753 words across six *sources* (the human author plus five models), all telling comparable premises, generated for a total API cost of about $4.4k.

### 8.2 A five-stage induction pipeline

Manually annotating narrative decisions across 60k long stories is infeasible, so the feature space itself is induced by LLMs, grounded in the ten-dimension NarraBench taxonomy of narrative structure (agent, social network, event, plot, structure, setting, time, revelation, perspective, and style) [@hamilton2025narrabench]:

```{mermaid}
flowchart LR
    A["61,608 stories from six sources"] --> B["Structured templates, GPT-5.1"]
    B --> C["Cross-source comparison on a 600-story pool"]
    C --> D["Feature discovery: 408 candidate questions"]
    D --> E["Embedding dedup to 304 features"]
    E --> F["Feature assignment, Gemini 3 Flash"]
    F --> G["Mixed-type encoding"]
    G --> H["XGBoost and SHAP"]
```

1. **Structured templates.** GPT-5.1 converts each story into a JSON template organized along the ten dimensions (character names, roles, and motivations for agent; causal chains and key events for event; and so on). The template is a controlled intermediate representation: downstream stages reason over narrative content, not prose.
2. **Cross-source comparison.** For a held-out discovery pool of 600 stories over 100 prompts, GPT-5.1 reads all six templates per prompt and writes a structured comparative analysis of where the sources diverge. This stage compresses roughly 2.7M tokens of raw text into about 686K tokens of observations.
3. **Feature discovery.** Ten dimension-specific expert prompts ask GPT-5.1 to propose discriminative features as closed-form questions with discrete answers. Three discovery runs yield 408 candidates, deduplicated by embedding clustering (cosine threshold 0.85), leaving $d = 304$ features in five response types: categorical (124), ordinal (59), scale (45), binary (44), and multi-select (32).
4. **Feature assignment.** Gemini 3 Flash annotates every story with all 304 features. Assignment is reliable: repeatability across five independent runs reaches Krippendorff's $\alpha = 0.88$, and agreement with human annotators on a 240-feature subset averages Cohen's $\kappa = 0.84$.
5. **Classification and attribution.** XGBoost classifiers [@chen2016xgboost] are trained on the encoded features, and SHAP [@lundberg2017shap] decomposes every prediction into per-feature contributions.

The design choice worth internalizing is the middle of the pipeline: instead of asking one model to simultaneously read, compare, and formalize, each stage consumes the previous stage's compressed artifact. That is what makes an interpretable feature space *inducible* at corpus scale.

### 8.3 Encoding a mixed-type feature vector

The annotation stage yields a typed semantic vector $z = (z_1, \dots, z_d)$ per story. The classifier does not consume $z$ directly; each feature is encoded according to its type,

$$
\phi_j(z_j) =
\begin{cases}
\operatorname{onehot}(z_j) \in \{0,1\}^{|V_j|} & \text{categorical with option set } V_j \\
\operatorname{multihot}(z_j) \in \{0,1\}^{|V_j|} & \text{multi-select} \\
z_j \in \{1, \dots, K_j\} & \text{ordinal and scale, kept numeric} \\
z_j \in \{0, 1\} & \text{binary}
\end{cases}
$$

and the encoded blocks are concatenated into $x = [\phi_1(z_1) \,\|\, \cdots \,\|\, \phi_d(z_d)] \in \mathbb{R}^D$. For the full 304-feature set $D = 1{,}108$; the narrative-only variant (257 features, all style features removed) has $D = 958$; the style-only variant (39 features) has $D = 129$. Splits are grouped at the prompt level (7,383 train, 1,405 validation, and 1,384 test prompts) so that no premise straddles train and test, the same leakage discipline as Section 7.5's rule about fitting vectorizers on the training fold only, applied one level up.

### 8.4 What 304 interpretable dimensions buy

The headline results, all macro-F1 on the held-out test set of 8,301 stories:

| Model | Features | Binary F1 | Binary AUPRC | 6-way F1 |
|---|---|---|---|---|
| Narrative only | 257 | 93.2 | .959 | 68.4 |
| Core only | 30 | 84.8 | .828 | 46.5 |
| Core + fingerprint | 101 | 91.1 | .934 | 63.4 |
| Narrative + style | 304 | 96.0 | .982 | 77.3 |
| Style only | 39 | 85.8 | .867 | 60.4 |
| ModernBERT (raw text) | | 99.9 | 1.00 | 99.8 |
| Stylometric + XGBoost (raw text) | 144 | 99.8 | .999 | 99.6 |
| TF-IDF + XGBoost (raw text) | 5,000 | 99.7 | .999 | 99.5 |
| Binoculars (zero-shot) | | 55.9 | .404 | |

Read the table through this chapter's lens. The raw-text baselines at the bottom are precisely the machinery of Sections 4 and 7: a 5,000-column TF-IDF matrix and a 144-feature stylometric vector, each feeding XGBoost, and they achieve near-perfect separation. On accuracy alone, classical surface features win. What the induced narrative features buy is different:

- **Interpretability.** Each of the 257 dimensions is a named, answerable question about the story ("is the resolution driven by the protagonist's choices?"), and SHAP attributes every single prediction to specific narrative decisions. A TF-IDF coefficient cannot tell an editor *why* a manuscript reads as machine-written.
- **Robustness to style editing.** When AI stories are rewritten with the LAMP span-level editing framework to remove characteristic AI phrasing (cliches, purple prose, redundant exposition) [@chakrabarty2025lamp], the narrative classifier barely moves: 93.9 versus 95.5 macro-F1 on the same stories unedited. Style detectors are brittle to exactly this attack.
- **Compactness.** Thirty core features retain 84.8 macro-F1. The human-AI boundary lives in a small, auditable subset of narrative decisions.
- **No length confound.** A length-only classifier reaches 55.9 macro-F1, and on a length-matched test subset the narrative model still scores 93.2, unchanged.

### 8.5 From SHAP to feature roles: core and fingerprint

The paper's post-hoc analysis is a model of disciplined feature selection. Importance and stability are assessed by bootstrap SHAP analysis: $B = 50$ prompt-level resampling iterations of the binary task, giving each feature $j$ a mean absolute SHAP importance $\bar{s}_j$, a bootstrap stability score $\operatorname{stab}_j$, a top-25 rate $\operatorname{top25}_j$ (how often the feature ranks among the 25 most important across iterations), and a permutation $p$-value $p_j$ against a shuffled-label null. A feature is *important* if $\bar{s}_j$ exceeds the top quartile of importances, and *stable-important* if its stability is at least the median among important features and its importance beats the 95th-percentile null with $p_j \le 0.10$. A *core* feature must clear all of that plus three magnitude thresholds:

$$
j \in \text{Core} \iff
\text{stable-important}(j)
\,\wedge\, \operatorname{stab}_j \ge 0.55
\,\wedge\, \operatorname{top25}_j \ge 0.60
\,\wedge\, |\Delta_j| \ge 0.20
\,\wedge\, \sigma_j^{\text{AI}} \le 0.35,
$$

where $\Delta_j$ is the human-AI gap in mean encoded value and $\sigma_j^{\text{AI}}$ is the spread of that mean across the five AI models (a core feature must separate humans from *all* models consistently, not from one). This yields 30 core features. *Fingerprint* features come from the six-way task instead: a feature qualifies when its SHAP importance concentrates in a single source class and that source's values visibly differ, yielding 75 fingerprint features, distributed very unevenly (human 32, Claude 26, GPT 11, Gemini 11, DeepSeek 7, Kimi 3).

The core features read like an editor's checklist of AI habits. AI stories over-explain themes (narrators state the moral 77% of the time versus 52% for humans), use dialogue for philosophical debate (59% vs. 34%), avoid subplots (79% subplot-free vs. 57%), resolve through protagonist choice (69% vs. 46%), and render emotion through bodies and senses (embodied emotion 81% vs. 38%, smell imagery 82% vs. 57%, explicit emotion labels only 8% vs. 29%). Human authors name real texts and authors (47% vs. 24%), break the fourth wall (67% vs. 39%), address the reader (28% vs. 7%), and write morally ambivalent protagonists (59% vs. 38%). The fingerprints are just as legible: Claude escalates events the least and favors epilogues over dream sequences, GPT over-indexes on gossip as a plot mechanism (64%) and on subverted expectations (41%), Gemini writes the tidiest endings and the bleakest settings (88% tagged bleak), DeepSeek front-loads crucial context, and Kimi sits at the generic center of the AI distribution with the fewest fingerprints and the lowest attribution F1.

### 8.6 A miniature StoryScope

The pipeline's downstream half fits in one code cell. The simulation below generates a parallel corpus in which each source's feature marginals are taken from the paper where reported (the core rates above, the fingerprint rates for GPT, Claude, and Gemini) and set to plausible illustrative values where the paper is qualitative, adds annotation noise consistent with the reported human-model agreement, then runs the paper's exact recipe: mixed-type encoding, a prompt-grouped split, XGBoost for binary detection and six-way attribution, and TreeSHAP importances straight from XGBoost's `pred_contribs` (no extra library needed).

```{python}
#| label: code-063-storyscope-mini
#| code-fold: false
import numpy as np
import pandas as pd
import xgboost as xgb
from sklearn.metrics import f1_score
from sklearn.model_selection import GroupShuffleSplit

rng = np.random.default_rng(7)

SOURCES = ["human", "claude", "gpt", "gemini", "deepseek", "kimi"]
N_PROMPTS = 1000

# Core-style binary features as (human rate, shared AI rate). Every pair is a
# marginal reported in the paper (sections 4.1 and 5).
CORE_RATES = {
    "narrator_explains_theme": (0.52, 0.77),
    "dialogue_as_philosophy":  (0.34, 0.59),
    "no_subplots":             (0.57, 0.79),
    "protagonist_resolution":  (0.46, 0.69),
    "olfactory_imagery":       (0.57, 0.82),
    "named_reference":         (0.47, 0.24),
    "addresses_reader":        (0.28, 0.07),
    "breaks_fourth_wall":      (0.67, 0.39),
    "ambivalent_protagonist":  (0.59, 0.38),
    "vague_allusions_only":    (0.50, 0.72),
    "balanced_reference_mix":  (0.37, 0.16),
    "subplots_serve_theme":    (0.42, 0.21),
    "acceptance_resolution":   (0.27, 0.47),
}

# One categorical feature: dominant mode of emotional expression. The explicit
# (29% vs 8%) and embodied (38% vs 81%) rates are the paper's; the remainder
# goes to behavioral cues.
EMOTION_LEVELS = ["explicit_label", "embodied", "behavioral"]
EMOTION_P = {"human": [0.29, 0.38, 0.33], "ai": [0.08, 0.81, 0.11]}

# 1-5 scale features as (human mean, AI mean). The explicitness pair is the
# paper's moral/philosophical weighting means (3.26 vs 3.68); the discontinuity
# gap is illustrative, direction only (humans jump across time more).
SCALE_MEANS = {
    "thematic_explicitness":       (3.26, 3.68),
    "chronological_discontinuity": (2.90, 2.30),
}

# Fingerprint features: a shared default rate plus per-model overrides. GPT's
# gossip (64%) and subversion (41%), Claude's continuism (62%), and Gemini's
# bleak settings (88%) are reported values; the defaults, the dream and
# epilogue rates, and the DeepSeek front-loading override are illustrative.
# Kimi deliberately gets no override, matching its 'generic center of the AI
# distribution' role in the paper.
FP_BASE = {
    "gossip_mechanism":      0.50,
    "subverts_expectations": 0.32,
    "continuist_tradition":  0.47,
    "bleak_setting":         0.55,
    "frontloads_context":    0.40,
    "dream_sequence":        0.10,
    "writes_epilogue":       0.30,
    "extended_denouement":   0.35,
}
FP_OVERRIDES = {
    "gpt":      {"gossip_mechanism": 0.64, "subverts_expectations": 0.41,
                 "dream_sequence": 0.30},
    "claude":   {"continuist_tradition": 0.62, "writes_epilogue": 0.55,
                 "dream_sequence": 0.03},
    "gemini":   {"bleak_setting": 0.88, "extended_denouement": 0.60},
    "deepseek": {"frontloads_context": 0.70},
}
# Claude's 'notably flat event escalation' as an illustrative scale gap.
ESCALATION_MEAN = {"claude": 2.1}
ESCALATION_DEFAULT = 3.0

ANNOTATION_FLIP = 0.02  # imperfect LLM annotation (human-model kappa is 0.84)

rows = []
for prompt in range(N_PROMPTS):
    for src in SOURCES:
        is_ai = src != "human"
        row = {"prompt": prompt, "source": src}
        for name, (h, a) in CORE_RATES.items():
            row[name] = rng.random() < (a if is_ai else h)
        row["emotion_mode"] = EMOTION_LEVELS[
            rng.choice(3, p=EMOTION_P["ai" if is_ai else "human"])
        ]
        for name, (h, a) in SCALE_MEANS.items():
            row[name] = int(np.clip(round(rng.normal(a if is_ai else h, 0.8)), 1, 5))
        for name, base in FP_BASE.items():
            row[name] = rng.random() < FP_OVERRIDES.get(src, {}).get(name, base)
        row["event_escalation"] = int(
            np.clip(round(rng.normal(ESCALATION_MEAN.get(src, ESCALATION_DEFAULT), 0.8)), 1, 5)
        )
        for name in list(CORE_RATES) + list(FP_BASE):
            if rng.random() < ANNOTATION_FLIP:
                row[name] = not row[name]
        rows.append(row)

df = pd.DataFrame(rows)

# Encode exactly as the paper does: one-hot for categorical, numeric for
# ordinal/scale, binary as-is.
X = pd.get_dummies(df.drop(columns=["prompt", "source"]),
                   columns=["emotion_mode"]).astype(float)
groups = df["prompt"].to_numpy()

# Prompt-level grouped split so no prompt straddles train and test.
train_idx, test_idx = next(
    GroupShuffleSplit(n_splits=1, test_size=0.25, random_state=0).split(X, groups=groups)
)

# Binary detection: human is the positive minority class at a 1:5 ratio, so we
# weight it 5x as the paper does.
y_bin = (df["source"] == "human").astype(int).to_numpy()
clf_bin = xgb.XGBClassifier(n_estimators=300, max_depth=6, learning_rate=0.1,
                            reg_lambda=2.0, scale_pos_weight=5.0,
                            eval_metric="logloss", random_state=0)
clf_bin.fit(X.iloc[train_idx], y_bin[train_idx])
f1_b = f1_score(y_bin[test_idx], clf_bin.predict(X.iloc[test_idx]), average="macro")

# Six-way attribution with the same features.
codes = {s: i for i, s in enumerate(SOURCES)}
y_six = df["source"].map(codes).to_numpy()
clf_six = xgb.XGBClassifier(n_estimators=300, max_depth=6, learning_rate=0.1,
                            reg_lambda=1.0, eval_metric="mlogloss", random_state=0)
clf_six.fit(X.iloc[train_idx], y_six[train_idx])
pred_six = clf_six.predict(X.iloc[test_idx])
f1_s = f1_score(y_six[test_idx], pred_six, average="macro")
per_class = f1_score(y_six[test_idx], pred_six, average=None)

print(f"binary human-vs-AI macro-F1:   {f1_b:.3f}"
      "   (paper: 0.932 with 257 features, 0.848 with the 30 core)")
print(f"six-way attribution macro-F1:  {f1_s:.3f}"
      "   (paper: 0.684 with 257 features, 0.465 with the 30 core)\n")
print("per-source F1 (paper ordering: human > Claude > GPT >> Gemini/DeepSeek/Kimi):")
for s in np.argsort(per_class)[::-1]:
    print(f"  {SOURCES[s]:<9} {per_class[s]:.3f}")

# SHAP via XGBoost's built-in TreeSHAP (pred_contribs), no extra library needed.
dtest = xgb.DMatrix(X.iloc[test_idx])
contrib_bin = clf_bin.get_booster().predict(dtest, pred_contribs=True)[:, :-1]
imp = np.abs(contrib_bin).mean(axis=0)
top = np.argsort(imp)[::-1][:6]
print("\ntop core features by mean |SHAP| (binary task):")
for j in top:
    print(f"  {X.columns[j]:<28} {imp[j]:.3f}")

# Multiclass SHAP: (n, classes, D+1). A fingerprint feature is one whose
# importance concentrates in a single source class.
contrib_six = clf_six.get_booster().predict(dtest, pred_contribs=True)[:, :, :-1]
imp_six = np.abs(contrib_six).mean(axis=0)
print("\ntop fingerprint feature per AI source (multiclass SHAP):")
for s in SOURCES[1:]:
    k = codes[s]
    j = int(np.argmax(imp_six[k]))
    print(f"  {s:<9} -> {X.columns[j]:<28} {imp_six[k, j]:.3f}")
```

The miniature reproduces the paper's qualitative structure with about two dozen features instead of 257. Binary detection is easy and lands near the paper's 30-feature core band; six-way attribution is much harder, exactly as in the paper, and sits between chance (0.167) and the core-only result because our eight fingerprint-style features cover only a sliver of the paper's 75. The per-source breakdown recovers the paper's ordering: the human class is easiest, Claude is the most separable AI source (its flat escalation and epilogue habit stick out), and Kimi, which by construction has no distinguishing marginal, is hardest, matching its role in the paper as the model with the fewest fingerprints. The binary SHAP ranking surfaces the features with the largest marginal gaps (embodied emotion, thematic explicitness), and the multiclass SHAP correctly concentrates each AI source's importance on its planted fingerprint. When importance is diffuse and weak, as for Kimi, that absence is itself the finding.

### 8.7 Running the real pipeline

The authors released the full replication package under the MIT license: the pipeline code, the 10,272 writing prompts, all 51,336 AI-generated stories, and the per-story feature vectors (human story texts are withheld for copyright reasons, since they derive from Books3). The repository is at [github.com/jenna-russell/storyscope](https://github.com/jenna-russell/storyscope), with the full dataset mirrored on Hugging Face as [`jjrussell10/storyscope`](https://huggingface.co/datasets/jjrussell10/storyscope). A 100-prompt dev slice (`data/stories_dev.parquet`), the final taxonomy (`data/taxonomy.json`), the extracted feature matrix (`data/storyscope_features.parquet`), and the trained XGBoost weights (`data/models/`) ship inside the repository itself, so the analysis stages run without spending anything on generation.

```bash
git clone https://github.com/jenna-russell/storyscope.git
cd storyscope
pip install -r requirements.txt
```

Providers and models for each stage are set in `config/models.yaml`, with API keys read from the environment (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, or `GOOGLE_CLOUD_PROJECT` depending on provider):

```yaml
pipeline:
  story_generation:
    provider: openai          # openai, anthropic, vertex, or huggingface
    model: gpt-5.4
  feature_application:
    provider: vertex
    model: gemini-3-flash
```

The six stages map one-to-one onto Section 8.2:

```bash
# 1. Generate stories from prompts
python -m storyscope.1_story_generation.generate_stories \
    --prompts data/prompts.json --output-dir outputs/stories --parallel 4

# 2. Extract structured narrative templates
python -m storyscope.2_template_extraction.extract_templates \
    --csv data/stories_dev.parquet --output-dir outputs/templates --parallel 4

# 3. Blinded cross-source comparison
python -m storyscope.3_cross_source_comparison.compare_sources \
    --templates-dir outputs/templates --output-dir outputs/comparisons --parallel 4

# 4. Induce the feature taxonomy (discover, union, dedup at cosine 0.85)
python -m storyscope.4_feature_discovery.discover_features \
    --comparisons-dir outputs/comparisons --output-dir outputs/taxonomy --runs 3
python -m storyscope.4_feature_discovery.build_taxonomy \
    --input-dir outputs/taxonomy --output outputs/taxonomy/union_taxonomy.json
python -m storyscope.4_feature_discovery.cluster_features \
    --taxonomy outputs/taxonomy/union_taxonomy.json \
    --output-dir outputs/taxonomy/clustered --sim-threshold 0.85

# 5. Apply the 304 features across the story corpus
python -m storyscope.5_feature_application.apply_features \
    --csv data/stories_train.parquet --taxonomy data/taxonomy.json \
    --output-dir outputs/features --parallel 24

# 6. Train classifiers and run bootstrap SHAP analysis
python -m storyscope.6_classification.train_classifier \
    --features data/storyscope_features.parquet --taxonomy data/taxonomy.json \
    --output-dir outputs/classification --task both
python -m storyscope.6_classification.shap_analysis \
    --features data/storyscope_features.parquet --taxonomy data/taxonomy.json \
    --output-dir outputs/shap --task both --bootstrap 50
```

Stages 1 through 5 call paid LLM APIs (the full corpus cost the authors roughly $4.4k); stage 6 is pure local compute on the shipped parquet files, which makes it the natural entry point for coursework and for extending the classifier analysis. As a closing note on the theme of this chapter: the highest-leverage feature engineering in this study was not done by a person writing extractors, it was done by one LLM interrogating the output of five others, with humans validating a sample of the annotations afterward.
